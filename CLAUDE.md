@AGENTS.md

The spec in `PRD.md` is the source of truth for scope, requirements, and phasing.

## Commands

`pnpm dev` · `pnpm build` · `pnpm lint` · `pnpm format` · `pnpm typecheck` · `pnpm test` · `pnpm test:e2e`

Before calling work done, run `pnpm lint && pnpm typecheck && pnpm test && pnpm build && pnpm test:e2e`. CI runs the same.

## Stack

Node 24 LTS, pnpm 12, Next.js 16 App Router, React 19 with React Compiler, TypeScript strict with `noUncheckedIndexedAccess`, Tailwind CSS v4, Biome, Vitest, Playwright.
Planned: shadcn/ui and Motion (add with the first UI phase), Zustand for the local profile, pdf.js for transcript import, Supabase for P1 login and sync only.

## Hard rules

- Real transcripts never enter the repo, not even in tests. Fixtures are synthetic.
- Transcript parsing runs only in the browser. The PDF never goes to a server.
- Catalogue data is generated by the crawler and lands through a reviewed PR. Never hand-edit generated catalogue files.
- The MVP has no backend. Profile data lives in browser storage.
- Unit test files are `*.test.ts`. Playwright files are `e2e/*.e2e.ts`.

## UI rules

- Mobile-first: every screen works at 320 px with no horizontal scroll, and touch targets are at least 44 by 44 px.
- Tap must work everywhere. Drag is a desktop extra, never the only way.
- Game animations respect `prefers-reduced-motion`.
